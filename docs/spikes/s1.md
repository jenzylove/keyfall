# Spike S1: can a contract tell a quantum-safe signer, and create quantum-only accounts?

**Question.** Does a NEAR contract see which key type signed the transaction? Can a contract create an account whose only key is ML-DSA-65?

**What was run.** `spikes/s1/contract` (raw host functions, no SDK key parsing) deployed to a fresh testnet account by `spikes/s1/script/run.mjs`, from the `spike-s1` GitHub Actions workflow. Run: https://github.com/jenzylove/qday/actions/runs/42384370462

**Output (testnet, protocol 88).**

| Check | Result | Evidence |
|---|---|---|
| ed25519 signer seen as key type 0 | Pass | https://testnet.nearblocks.io/txns/3s92pAY4sJGpGH8tcadhcoq2PiReU2mBGmndjtw7PDy6 |
| ML-DSA-65 key added to the account | Pass | https://testnet.nearblocks.io/txns/LhgcrZB2Jmo81zaFPFTmpS8a8YrwvgQKttL6wJRphZc |
| ML-DSA-65 signer seen as key type 2 (1,953-byte key) | Pass | https://testnet.nearblocks.io/txns/5uTd2NZnLLGJFgvfLynuLSkAj7FPgqFze1Cjv8LJH28m |
| Quantum-only method refuses ed25519 (`E_NOT_QUANTUM`) | Pass | https://testnet.nearblocks.io/txns/A7w6q9r2foad8X4zjQukgopQf4fB58xCW8YLJ2VhXWPS |
| Quantum-only method accepts ML-DSA-65 | Pass | https://testnet.nearblocks.io/txns/AieifYASR1FLoBgPE9DyNyobH4utrWfKVBGnZSZ3ThbK |
| Contract creates a sub-account with one ML-DSA-65 full-access key | Pass | https://testnet.nearblocks.io/txns/5Ad7jg6uTqV59KpjCYuryUoyQUWATL9YitE635pregyE |
| That account signs its own transaction with ML-DSA-65 | Pass | https://testnet.nearblocks.io/txns/AE5fA5oP68HqwPrjcoEfmqE1ijBfse8Cp3bUjj4wztM4 |
| Relayed (meta) transaction signed inside with ML-DSA-65 | Finding: the contract sees the **relayer's** ed25519 key | https://testnet.nearblocks.io/txns/7tCZ2apoRdC2NF29rMzqsoMraA4FvjfA5adyXwukCrgt |

**Verdict.** Pass. The mechanic is real. Game moves must be signed directly by the vault, not relayed. A new account funded with exactly 0.05 NEAR could not pay for its first ML-DSA-65 transaction; fund vaults with more.
